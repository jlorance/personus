# Platform Integrations — Discord

> Date: 2026-02-23 (revised 2026-05-11)
> Status: Draft — first-class platform; **implementation vehicle is Mastra Channels** (see §0)
> Depends on: `00-overview.md`, `01-shared-architecture.md`, `03-bot-architecture.md`
> Tracking: **PER-64** — Discord integration is the first Mastra Channels adapter to ship
> Prereq: PER-5 / PER-6 / PER-17 (principal delegation contract)

Discord is a **first-class integration platform** for Personus. Its official Bot API, slash commands, rich interactive components, and 200M+ MAU make it the dominant community platform in gaming, tech, and creator spaces.

---

## 0. Implementation Update — Mastra Channels (2026-05-11)

This spec was originally written assuming a hand-rolled HTTP Interactions Endpoint at `app/api/discord/interactions/route.ts` (Ed25519 verification, BotCommand parsing, deferred response handling). As of Mastra 1.26 we are **using `@chat-adapter/discord` + Mastra Channels** instead. See `03-bot-architecture.md §0` for the full rationale.

**What changes:**

- The HTTP Interactions Endpoint is **auto-generated by Mastra** at `/api/agents/{agentId}/channels/discord/webhook`. We register that URL in the Discord developer portal; we do not write the route handler.
- Ed25519 signature verification, dedup, thread context, DM vs. mention routing, and the `add_reaction` / `remove_reaction` tools all come from `@chat-adapter/discord`.
- Slash command *definitions* (the seven commands listed in §6 below) still live in our Discord application manifest. The *handling* runs through the agent's tool-call loop, not a switch statement.

**What stays in this spec:**

- §§1-3 (strategic position, platform fundamentals, per-platform inputs) — unchanged.
- §§4-5 (auth flow, `platform_channel_bindings` table) — unchanged.
- §6 (command surface) — descriptions still drive the slash command manifest and the agent's tool descriptions. The control flow diagram is now `slash command → Channels webhook → agent → Personus tools` rather than the BotCommand router.
- §§9+ (rate limits, error handling, observability) — Mastra Channels handles webhook-side concerns; outbound Discord API rate limits still need attention if/when we deferred-respond with rich embeds.

**Tier 4 (member sync, Gateway WebSocket) is unaffected** — Mastra Channels does not cover Gateway intents. If we need Tier 4 we still need a Fly.io process as described in `03-bot-architecture.md §3-5`.

## 1. Strategic Position

### 1.1 Why Discord Is First-Class

| Strength | Detail |
|---|---|
| **Official Bot API** | Mature, well-documented, actively developed. Bots are a first-class Discord feature. |
| **Slash commands + rich UI** | Typed parameters, autocomplete, subcommands, buttons, select menus, modals. The richest command system of any chat platform. |
| **Member list access** | Can enumerate all guild members (with `GUILD_MEMBERS` intent). Unique advantage over Telegram. |
| **Message history** | Can read channel history. Enables retroactive community analysis. |
| **Role system** | Arbitrary custom roles with colors, permissions, hierarchy. Maps to Personus community roles. |
| **HTTP Interactions** | Slash commands can be received via HTTP POST (serverless-compatible). No Gateway needed for Tier 3. |
| **200M+ MAU** | Dominant in tech, gaming, creator, and education communities. |

### 1.2 Risk & Compliance

| Factor | Assessment |
|---|---|
| API stability | Excellent — versioned API, deprecation notices, stable breaking change cycle |
| ToS alignment | Bots are officially supported and encouraged |
| Data privacy | Bot receives: username, display name, avatar, roles, join date. No email or phone. |
| Rate limits | Well-documented, generous for most use cases |

### 1.3 What We're Building

| Tier | Scope | Hosting |
|---|---|---|
| **Tier 1: Link** | `discord.gg` invite parsing, community badge | Shared architecture (01) |
| **Tier 2: Notify** | Outbound webhooks to Discord channels | Next.js server action (fire-and-forget HTTP POST) |
| **Tier 3: Interact** | Slash commands, buttons, modals | Next.js API route (HTTP Interactions Endpoint) |
| **Tier 4: Sync** | Member sync, join/leave events, activity | Separate bot process (deferred — see `03-bot-architecture.md`) |

**Key insight:** Discord slash commands can run via HTTP Interactions Endpoint (no Gateway WebSocket needed). This means **Tier 1-3 runs entirely in Next.js** — no separate bot process required until Tier 4.

## 2. Platform Fundamentals

### 2.1 Discord Concepts

| Concept | Personus Mapping |
|---|---|
| **Guild** (server) | Maps to one Personus community |
| **Channels** | Text channels where bot commands are used |
| **Roles** | Map to Personus community member roles (steward, admin, member) |
| **Threads** | Conversation context for introductions or search results |
| **Forum Channels** | Similar to Telegram Topics — structured discussions |

### 2.2 Permissions & Intents

Discord bots request permissions at install time and receive data based on Gateway Intents.

**Permissions needed (OAuth2 scope):**

| Permission | Why |
|---|---|
| `bot` | Add bot user to the guild |
| `applications.commands` | Register slash commands |
| `Send Messages` | Respond to commands |
| `Embed Links` | Rich embed responses |
| `Read Message History` | Context for searches (Tier 4) |
| `Manage Roles` | Map roles to Personus tiers (optional) |
| `View Channel` | See channels the bot is in |

**Gateway Intents (Tier 4 only):**

| Intent | Why | Privileged? |
|---|---|---|
| `GUILDS` | Guild metadata, channel info | No |
| `GUILD_MEMBERS` | Member join/leave, member list | **Yes** — requires Discord developer portal approval at 100+ guilds |
| `MESSAGE_CONTENT` | Read message content (Tier 4 activity) | **Yes** — requires approval |

**Tier 3 does not need Gateway Intents** — HTTP Interactions Endpoint receives slash commands directly.

### 2.3 Key Differences from Other Platforms

| Feature | Discord | Telegram | Matrix | Slack |
|---|---|---|---|---|
| Member list enumeration | **Yes** | No | Via Appservice | **Yes** |
| Message history access | **Yes** | No | Via Appservice | **Yes** |
| Rich slash command params | **Yes** (typed, autocomplete) | Basic `/cmd text` | N/A (text commands) | Basic `/cmd text` |
| Embedded web app | No | Mini Apps | Widget API | No |
| Custom roles | **Yes** (full hierarchy) | Admin/member only | Power levels | Limited |
| Serverless commands | **Yes** (HTTP Interactions) | **Yes** (webhooks) | No | **Yes** (Events API) |

## 3. Per-Platform Inputs

When a Community Organizer connects Discord:

| Field | Type | Required | Placeholder | Notes |
|---|---|---|---|---|
| Invite link | url | Either this or server ID | `https://discord.gg/abc123` | Primary input |
| Server ID | text | Either this or link | `123456789012345678` | Advanced, collapsible |

**Auto-parse:** `discord.gg/<code>` or `discord.com/invite/<code>` → extract invite code.

**Parser function:**

```typescript
const DISCORD_INVITE_REGEX = /^https?:\/\/(?:discord\.gg|discord\.com\/invite)\/([a-zA-Z0-9\-]+)$/;

export function parseDiscordInviteUrl(url: string): { inviteCode: string } | null {
  const match = url.match(DISCORD_INVITE_REGEX);
  if (!match) return null;
  return { inviteCode: match[1] };
}
```

**Validation schemas:**

```typescript
export const discordGuildIdSchema = z.string().regex(/^\d{17,20}$/, 'Invalid Discord server ID');
export const discordInviteCodeSchema = z.string().regex(/^[a-zA-Z0-9\-]+$/, 'Invalid invite code');

export const connectDiscordSchema = z
  .object({
    communityId: z.string().uuid(),
    inviteUrl: z.string().url().optional(),
    guildId: z.string().optional(),
    inviteCode: z.string().optional(),
  })
  .refine(
    (data) => !!(data.inviteUrl || data.guildId),
    { message: 'Provide a Discord invite link or server ID' },
  )
  .transform((data) => {
    if (data.inviteUrl && !data.inviteCode) {
      const parsed = parseDiscordInviteUrl(data.inviteUrl);
      if (parsed) data.inviteCode = parsed.inviteCode;
    }
    return data;
  });

export type ConnectDiscordInput = z.infer<typeof connectDiscordSchema>;
```

**Stored as:**
```json
{
  "platform": "discord",
  "label": "Discord",
  "url": "https://discord.gg/abc123",
  "inviteCode": "abc123",
  "guildId": "123456789012345678"
}
```

## 4. Integration Architecture by Tier

### 4.1 Tier 1: Link (Shared Architecture)

Handled by `01-shared-architecture.md`. Discord invite link stored in `communities.externalPlatforms` JSONB. Badge displayed on community profile. AI agents report Discord presence.

### 4.2 Tier 2: Notify (Discord Webhooks)

Discord has native webhook support — no third-party bridge needed (unlike Matrix's Hookshot).

**How it works:** Community Organizer creates a Discord webhook in their server settings, gives Personus the URL. Personus POSTs formatted messages.

**Webhook helper:**

```typescript
// lib/discord/webhooks.ts

export async function sendDiscordWebhook(
  webhookUrl: string,
  message: {
    content?: string;
    embeds?: DiscordEmbed[];
    username?: string;
    avatar_url?: string;
  },
) {
  try {
    const response = await fetch(webhookUrl, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        content: message.content,
        embeds: message.embeds,
        username: message.username || 'Personus',
        avatar_url: message.avatar_url,
      }),
    });
    return { success: response.ok, status: response.status };
  } catch (error) {
    console.error('Discord webhook failed:', error);
    return { success: false, error: String(error) };
  }
}

interface DiscordEmbed {
  title?: string;
  description?: string;
  color?: number;       // decimal color (e.g., 0x5865F2 for Discord blurple)
  fields?: { name: string; value: string; inline?: boolean }[];
  footer?: { text: string };
  timestamp?: string;   // ISO 8601
}
```

**Notification events** (same as Matrix — fire when `config.notifyChannel` is set):

| Event | Embed Format |
|---|---|
| New member joins | Embed with name, skills summary, avatar. Color: green. |
| Endorsement given | Embed with endorser, endorsee, skill. Color: gold. |
| Contact request | Embed with "New introduction request" (no names). Color: blue. |

**Setup flow:**
1. Organizer goes to Discord Server Settings → Integrations → Webhooks → New Webhook
2. Selects a channel, copies the webhook URL
3. Pastes into Personus Settings → Connections → Discord → Configure → Notification webhook

### 4.3 Tier 3: Interact (Slash Commands via HTTP)

Discord supports receiving slash command interactions via an **HTTP Interactions Endpoint** — a URL that Discord POSTs to when a user invokes a command. This is serverless-compatible and runs in Next.js.

**Webhook endpoint:**

```typescript
// app/api/discord/interactions/route.ts
export const dynamic = 'force-dynamic';

import { verifyDiscordRequest } from '@/lib/discord/verify';

export async function POST(request: Request) {
  const body = await request.text();
  const signature = request.headers.get('X-Signature-Ed25519');
  const timestamp = request.headers.get('X-Signature-Timestamp');

  if (!verifyDiscordRequest(body, signature, timestamp)) {
    return new Response('Invalid signature', { status: 401 });
  }

  const interaction = JSON.parse(body);

  // Discord sends a PING to verify the endpoint
  if (interaction.type === 1) {
    return Response.json({ type: 1 }); // PONG
  }

  // Slash command
  if (interaction.type === 2) {
    return handleSlashCommand(interaction);
  }

  // Button / select menu / modal submit
  if (interaction.type === 3) {
    return handleComponentInteraction(interaction);
  }

  return Response.json({ type: 1 });
}
```

**Signature verification:**

```typescript
// lib/discord/verify.ts
import { verify } from 'discord-interactions'; // or use tweetnacl

export function verifyDiscordRequest(
  body: string,
  signature: string | null,
  timestamp: string | null,
): boolean {
  if (!signature || !timestamp) return false;
  const publicKey = process.env.DISCORD_PUBLIC_KEY!;
  return verify(body, signature, timestamp, publicKey);
}
```

**Proposed slash commands:**

| Command | Parameters | Response |
|---|---|---|
| `/personus discover` | `query: string` | Embed with matching members + buttons |
| `/personus who-knows` | `skill: string` | Embed with members who have that skill |
| `/personus profile` | `user: @mention` | Embed with persona card + action buttons |
| `/personus intro` | `user: @mention`, `message: string` | Confirm embed → starts mediated intro |
| `/personus community` | (none) | Community skill summary embed |
| `/personus link` | (none) | Ephemeral message with link to Personus onboarding |
| `/personus help` | (none) | Ephemeral message listing commands |

**Slash command registration:**

```typescript
// lib/discord/register-commands.ts
// Run once (or on deploy) to register slash commands with Discord API

const COMMANDS = [
  {
    name: 'personus',
    description: 'Personus community intelligence',
    options: [
      {
        name: 'discover',
        description: 'Search for members with specific skills',
        type: 1, // SUB_COMMAND
        options: [
          { name: 'query', description: 'What are you looking for?', type: 3, required: true },
        ],
      },
      {
        name: 'who-knows',
        description: 'Find someone who can help',
        type: 1,
        options: [
          { name: 'skill', description: 'The skill or knowledge area', type: 3, required: true },
        ],
      },
      {
        name: 'profile',
        description: 'View a member\'s Personus profile',
        type: 1,
        options: [
          { name: 'user', description: 'The member to look up', type: 6, required: true }, // USER type
        ],
      },
      {
        name: 'intro',
        description: 'Request an introduction to a member',
        type: 1,
        options: [
          { name: 'user', description: 'Who you want to meet', type: 6, required: true },
          { name: 'message', description: 'Why you want to connect', type: 3, required: false },
        ],
      },
      { name: 'community', description: 'View community skill summary', type: 1 },
      { name: 'link', description: 'Link your Personus account', type: 1 },
      { name: 'help', description: 'Show available commands', type: 1 },
    ],
  },
];

export async function registerCommands(guildId?: string) {
  const url = guildId
    ? `https://discord.com/api/v10/applications/${process.env.DISCORD_APPLICATION_ID}/guilds/${guildId}/commands`
    : `https://discord.com/api/v10/applications/${process.env.DISCORD_APPLICATION_ID}/commands`;

  const response = await fetch(url, {
    method: 'PUT',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bot ${process.env.DISCORD_BOT_TOKEN}`,
    },
    body: JSON.stringify(COMMANDS),
  });

  return response.json();
}
```

**Interaction response pattern:**

```
User: /personus discover TypeScript
Discord POSTs to: /api/discord/interactions

Personus responds immediately with:
  Type 5 (DEFERRED_CHANNEL_MESSAGE_WITH_SOURCE) — "Searching..."

Personus calls semantic search in background, then:
  PATCH /webhooks/{app_id}/{interaction_token}/messages/@original

Updated message:
  Embed: "Found 3 members with TypeScript skills"
  Fields: Alice (5+ years), Bob (React+TS), Carol (Node+TS)
  Buttons: [View Alice] [View Bob] [View Carol] [More Results]

User clicks [View Alice]:
  Discord POSTs component interaction
  Personus responds with Alice's profile embed + [Request Intro] [Back]
```

**Why deferred responses matter:** Personus semantic search may take 2-5 seconds. Discord requires a response within 3 seconds. Use `DEFERRED_CHANNEL_MESSAGE_WITH_SOURCE` (type 5) to acknowledge immediately, then follow up with the actual results via webhook edit.

### 5.3 Account Linking Flows

**From Discord (slash command → web auth):**
```
User: /personus link
Bot responds (ephemeral): "Link your Personus account: [Click here]"
  → Button URL: https://personus.ai/link/discord?state={encrypted_discord_user_id}
  → User authenticates with Clerk on personus.ai
  → On success: stores discordUserId on user record
  → Bot can now map Discord user → Personus persona
```

**From Personus (settings → Discord OAuth):**
```
User goes to Settings → "Link Discord Account"
  → Discord OAuth2 flow (identify scope)
  → Returns Discord user ID, username, avatar
  → Stores discordUserId on user record
```

**Auto-link on slash command (Tier 3):**
When a linked user runs `/personus discover`, the bot knows their Personus identity and can personalize results (e.g., exclude skills they already have, prioritize their community).

## 8. Rate Limits & Design Constraints

| Constraint | Limit | Design Response |
|---|---|---|
| Interaction response | 3 seconds | Use deferred responses (type 5), then follow up via webhook edit |
| Follow-up edits | 15 minutes after interaction | Complete all operations within 15 min window |
| Global API rate | 50 requests/second per route | Queue with backoff |
| Channel messages | 5 messages / 5 seconds | Use embeds + buttons, not multiple messages |
| Embed fields | 25 fields per embed | Paginate search results (5-8 per page) |
| Embed description | 4096 characters | Truncate long profiles |
| Slash command options | 25 options per command | Use subcommands for organization |
| Button rows | 5 buttons per row, 5 rows | Paginate with prev/next |

| **Tier 4: Sync** | Member list, join/leave, roles | Deferred | Separate process | Needs `discord.js` Gateway |
| **Tier 5: Embed** | Personus UI inside Discord | No | — | Discord has no embedded web app capability |

## 12. Discord-Specific Considerations

### 12.1 Ephemeral Responses

Some commands should respond ephemerally (only visible to the invoking user):
- `/personus link` — personal account linking
- `/personus help` — command reference
- `/personus profile` when viewing own profile

Skill searches and community queries should be **public** — the whole point is community visibility.

### 12.2 Thread-Based Introductions

When `/personus intro @alice` is invoked, the bot could create a **private thread** for the introduction conversation. This keeps the mediation visible to the parties but out of the main channel.

### 12.3 Role Mapping

Discord roles can map to Personus community roles and guild tiers:

```typescript
// Example role mapping in integration config
{
  roleMapping: {
    '123456789': 'steward',    // Discord role ID → Personus role
    '234567890': 'admin',
    '345678901': 'member',
  },
  tierMapping: {
    '456789012': 'master',     // Discord role ID → Guild tier
    '567890123': 'journeyman',
    '678901234': 'apprentice',
  },
}
```
